# ADR-002 状态同步模型：服务端权威 + 个性化全量视图广播

- 状态：**Accepted**（2026-08-02，程基岩）
- 上下文：合作桌游存在**隐藏信息**（各自手牌、牌库顺序、背面朝下的待收书信与通牒卡）；4 人实时房间；客户端零信任（测试版也要防"看牌"泄漏）；动作频率为人手操作级（峰值 < 1 次/秒/人）。

## 决策

1. **服务端权威**：规则只在服务端运行。客户端发送意图 Command → 服务端鉴权（座位/轮次/费用前置校验由引擎完成）→ `applyCommand` 产出新状态与事件。
2. **按座位投影后全量广播**：每次变更对每个连接执行 `view = projectView(state, seat)` 全量推送。投影规则：
   - 他人手牌 → 仅数量；个人牌库 → 仅数量；弃牌堆 → 公开（实体游戏可查）；
   - 公共牌库（危机/羁绊/传书）→ 仅数量，顶牌仅在规则明示"查看"时对该玩家可见；
   - 待收书信 → 仅发送方与接收方座位可见牌面（其余见"存在一封"）；通牒卡 → 全员不可见。
   - 事件流同样按座位脱敏（如 `card_drawn` 的牌面对非属主置空）。
3. **房间级单调 seq**：视图带 `{ seq }`，客户端丢弃 ≤ 当前值的乱序包；不追求增量合并。
4. **无客户端预测**：合作 PvE 手感对延迟不敏感，以服务端确认为唯一真相。

## 备选与否决理由

1. **状态广播（主机权威 / P2P）**：某玩家客户端做权威主机。否决——隐藏信息必须对客户端保密，规则计算放在任何玩家机器上都会泄漏全量状态；且主机离开即散局。
2. **JSON Patch / 增量 diff 广播**：带宽节省在本规模无意义（快照 < 50KB），却引入补丁乱序/漏帧漂移风险。否决；若未来观战/回放需要再议。
3. **锁步输入广播（确定性同步）**：引擎虽确定性，但锁步要求所有客户端跑同一引擎且处理断线复杂。否决——不过确定性引擎为它留了门（回放调试即用此性质）。

## 后果

- 正面：任何时刻任意客户端崩溃/重连，一条全量视图即恢复一致；测试只需断言投影函数。
- 代价：每次变更广播 4 份个性化视图（CPU 可忽略）；客户端无法做任何规则预判（可接受）。
- 安全：`projectView` 是**唯一的**信息出口，必须被单测钉死（已交付 `view.test.ts`）；新增状态字段时默认隐藏、显式公开（见 control-manifest）。
