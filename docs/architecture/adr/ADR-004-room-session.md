# ADR-004 房间与会话生命周期：内存注册表 + token 重连

- 状态：**Accepted**（2026-08-02，程基岩）
- 上下文：测试版只需要"能开房、能 4 人连、断线能回来"；无账号体系；单进程部署。

## 决策

1. **内存房间注册表**：`Map<roomId, Room>`，roomId 为 4 位无歧义字符码（去 0O1IL）。无数据库。
2. **生命周期**：`lobby`（加入/离开/主机可开局）→ `playing`（指令流转）→ `finished`（game_over 后只读，可解散）。
3. **座位与角色映射**：按加入顺序落座 0..N-1；开局时由人数规则导出映射——4 人各控 1 名（小鱼→莉雅→凯尔→巴爷按座）；3 人由主机开局参数指定弃凯尔或巴爷；1–2 人固定小鱼+莉雅，单人 0 号座双控。
4. **重连**：入座签发 `{ playerId, token }`（crypto 随机）；断线标记 `connected:false` 保留座位；凭 `roomId+token` 重连恢复座位并补发最新视图。token 即本测试版全部"身份"，客户端自行保存（localStorage）。
5. **指令鉴权**：`cmd` 仅当发送者座位控制当前行动角色（或该指令为任意时机指令，如材料转让——Task #1 细化）才递交引擎；引擎错误原样回执发送者，不污染他人。
6. **心跳**：ws ping/pong 30s，超时断连标记离线（不踢出）。

## 备选与否决理由

1. **持久化房间（SQLite/文件快照）**：续局能力好，但测试版进程重启即重开可接受，引入持久化拉高实现与测试面。否决，留为后续增强。
2. **Socket.IO 房间**：见 ADR-001，自写注册表换取协议透明。
3. **出局即踢人**：断线 4 人局少一人无法继续（合作游戏无 AI 代打），保留座位等回归是唯一合理选择。

## 后果

- 正面：实现 ~300 行；集成测试用真实 WebSocket 全链路覆盖。
- 代价：单进程容量上限即全部容量（测试版 4 人 × 若干房间，无虞）；无横向扩展路径（不需要）。
