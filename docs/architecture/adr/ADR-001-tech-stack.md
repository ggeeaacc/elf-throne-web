# ADR-001 技术栈选型：TypeScript 全栈 + ws + Vite

- 状态：**Accepted**（2026-08-02，程基岩）
- 上下文：规则 100% 忠实优先；美术零要求；1–4 人房间制实时联机；本机仅托管 Node 22.22.2 且禁全局安装；团队后续要写大量规则回归测试。

## 决策

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | **TypeScript 5.6 严格模式**（engine/server/client 同构） | 规则 schema 即类型；一套类型三端共享，杜绝协议漂移 |
| 引擎运行时 | **零依赖纯 TS** | 可在 node 与浏览器双端运行，单测无环境成本 |
| 服务端 | **node:http + ws 8** | 唯一运行时依赖；协议完全自控 |
| 客户端 | **Vite 6 + 原生 TS/DOM** | 无框架；极简 UI 用框架是纯负担 |
| 测试 | **Vitest 3** | TS 原生、引擎/服务端共用一套 runner |
| 包管理 | **npm workspaces**（engine/server/client） | 全部本地安装，无全局污染 |

## 备选与否决理由

1. **Socket.IO** — 自带房间/重连/降级，但协议黑盒、依赖重（engine.io 全家桶）。4 人房间内自写 200 行会话管理即可，换取协议显式可控。**否决**。
2. **React/Vue 客户端** — 状态驱动 UI 更爽，但用户明确「美术零要求、能测即可」，DOM 直写 < 200 行。**否决**（若 Task #3 交互膨胀可复议，迁移成本因视图模型薄而可控）。
3. **Colyseus 等游戏服务器框架** — 内置权威房间与状态同步，但引入其状态哲学（schema 注解 + patch 广播）会与「纯函数引擎 + 个性化视图」冲突，且规则引擎才是本项目核心资产，不该被框架绑定。**否决**。
4. **Node 原生 test runner**（零安装）— 可用，但 watch/断言/覆盖率体验弱于 vitest，网络可用下没有理由省。**否决**。

## 后果

- 正面：全栈同语言同类型；engine 零依赖可被 QA 直接驱动做回归；冷启动 `npm install && npm start` 两条命令。
- 代价：ws 需自己实现重连/心跳（ADR-004，约百行）；Vite 开发端口与 :8787 分离，已用代理解决。
- 中性：TypeScript 严格模式（`exactOptionalPropertyTypes`、`noUncheckedIndexedAccess`）提高书写成本，换取规则代码的编译期护栏——对本项目值得。
