## 1. 测试分层策略

| 层 | 名称 | 工具 / 位置 | 覆盖目标 | 门控 |
|---|---|---|---|---|
| L0 | 引擎单元测试 | Vitest · `engine/src/*.test.ts`（现有 35 条）+ `tests/unit/` | 纯函数 `applyCommand` 逐规则断言：数值口径、卡牌效果、状态机转换、费用/上限 | 每次提交全绿 |
| L1 | 状态机集成测试 | Vitest · `tests/integration/` | 跨相位/跨轮联动：P1→P4 管线、bondLead 跨轮、失控倒计时跨常规/决战、传书跨回合 | 每次提交全绿 |
| L2 | 端到端对局回放 | Vitest · `tests/replay/` + `scripts/smoke.mjs` 扩展 | 固定种子整局指令流回放：1/2/3/4 人各 ≥1 局打穿常规 9 轮 + 决战至终局；黄金终态逐字节比对 | 合并前必跑 |
| L3 | 联机同步测试 | Vitest · `server/src/*.test.ts` + 手工 | WS 建房/入座/鉴权/投影脱敏/断线重连/seq 单调；服务端零规则 | 合并前必跑 |

- **验证驱动**：Task #1 引擎实现必须与用例转码同步推进——每张卡牌效果、每条状态机转换先有用例断言再实现（CLAUDE.md 红线）。
- **确定性是测试基座**：引擎纯函数 + 种子 RNG（mulberry32），同种子同指令流 ⇒ 逐字节同终态；全部用例禁止依赖时钟与真随机。
- **决策点测试法**：凡规则含"玩家协商/选定"（通用危机卡落点、偏见触发对、多代受承受者、分摊高份归属、效果链声明顺序、危-06 装备归属、轮末效果定序），用例一律经由 `pendingDecision` → `resolve_decision` 驱动，断言中断点与续算结果两侧。

## 2. 规则断言引证格式（与工程的双向追溯约定）

### 2.1 用例编号

`TC-<系统前缀>-<三位序号>`，系统前缀固定 13 个：

| 前缀 | 系统 | 前缀 | 系统 |
|---|---|---|---|
| TC-MD | 人数变体与开局 SETUP | TC-BD | 偏见与羁绊（含 10 张羁绊卡） |
| TC-PH | 相位状态机与时间轴 | TC-LT | 传书（含 5 种传书卡） |
| TC-SC | 场景行动与移动/飞空艇 | TC-FG | 锻造与装备（含 5 种装备） |
| TC-CR | 危机蔓延与危机卡（10 种） | TC-CD | 角色专属卡（40 张） |
| TC-CB | 交战结算与伤害效果链 | TC-FB | 最终决战（备战/三阶段/宝玉） |
| TC-WL | 胜负判定与出局 | TC-SY | 联机同步与确定性 |
| TC-ER | 侵蚀与失控状态机 | | |

### 2.2 引证串（每条用例强制）

```
引证：【§<rules-spec 章节号>】【L<规则书行号>】【裁A-<裁定编号>】
```

1. 每条用例**至少一个 `【§】`**；能定位到规则书原文行号的必须带 `【L】`；涉及 44 条裁定的必须带 `【裁A-xx】`；涉及冻结后新增裁定的带 `【裁Q-x】`（登记于本文件 §10）。
   例外：**TC-SY 中联机基础设施用例**（无规则来源，如房间/重连/反作弊）允许以 `【ADR-xxx】` 替代 `【§】`；规则相关用例不适用此例外。
2. 引证对象为**断言的来源**，不是"相关阅读"；一条断言一个引证串，多个来源并列书写。
3. 用例 ↔ 规格双向可追溯：正向在用例末尾；反向索引见本文件 §4（裁定→用例）与附录 A（章节→用例）。

### 2.3 Vitest 内嵌规范（工程转码时遵守）

```ts
it('TC-CB-009 效果链声明顺序敏感：×2 与 +2 次序决定结果【§11】【裁A-08】', () => { ... });
```

- `it` 标题 = `TC编号 + 标题 + 引证串`，三者缺一不可；`describe` 用系统中文名（如 `describe('侵蚀与失控状态机', ...)`）。
- 一条用例可拆多个 `it`，但每个 `it` 都必须带同一 TC 编号与引证串（后缀 `-a/-b` 区分）。

### 2.4 CI 校验（Task #4 后半段落地 `scripts/check-citations.mjs`）

- 扫描 `tests/` 下所有 `it` 标题：**无 TC 编号或缺引证串 → 报错**（INVALID）。
- 对照 rules-spec.md 章节清单与 ambiguities.md 44 条：**无用例覆盖 → COVERAGE GAP 报告**，回归 designer/QA 补例。
- 现有 `engine/src/*.test.ts` 35 条保留有效，转码时逐步在标题对齐 TC 编号（映射见 §6）。

## 7. 烟雾测试门控（PASS / FAIL 标准）

**门控 = 建议性（advisory）；最终放行由用户签字。**

PASS 需同时满足：
1. `npm test` 全绿（L0+L1+L3）；
2. `npm run smoke` 通过（构建 + 建房→4 人入座→开局→行动→推进至决战）；
3. L2 回放：**4 人局完整打穿**（常规 9 轮 → 决战 → 终局）终态与黄金快照逐字节一致；
4. P0 用例 0 FAIL；flaky 隔离区 0 增长。

FAIL 即"未达 QA"的典型阻塞项：任何胜负判定时点错误；冻结数值口径偏差（玫拉 12/6、阈值 floor、翻牌量 13/16、分摊守恒等）；44 条裁定任一未实现或实现偏离；同种子回放终态漂移。

## 8. 测试稳定性（flaky）政策

- 一切随机经由种子 RNG；用例禁止 `Date.now`/`Math.random`/真定时器依赖。
- 疑似 flaky：连续 3 次本地复跑不一致 → 立即打 `quarantine` 标签移出门控，24h 内定位（优先查：未固定种子的 fixture、pendingDecision 未闭合、迭代顺序依赖），修复并补回归后方可回移。
- 隔离区用例不计入 PASS 分母，但**禁止长期滞留**（>1 周未处理升级 team-lead）。

## 9. Playtest 签收要求（L2/L3 之外的人工验收）

四人局完整打穿 1 局，checklist 必到事件：P3 偏见至少触发 1 次且结成 1 组羁绊；小鱼失控至少 1 次并解除（或 F4 判负路径确认）；传书往返 ≥2 次（激活羁-01 或替换羁-02）；锻造 ≥2 次（含 1 次折扣）；决战完整经历护盾→P2→P3 三阶段；1P/2P 局各开局验证差分（P3 跳过、补给抽 2）。记录落 `production/playtests/`。
